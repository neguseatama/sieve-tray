# 名前の整理（rename）の手順

`rename` は、フォルダの中のファイル名を決まった規則で整える計画を作ります。
既定では何も書き換えず、計画（`local/rename-plan.json`）と処理記録
（`handoff/rename-receipt.json`）だけを出します。`--apply` を付けると、
出力先の `renamed/` に整えた複製を作ります。元のフォルダは byte 等価のまま
変わりません。

## 1. 規則（`--pattern`）

規則は、そのままの文字とフィールドを組み合わせて書きます。書けるフィールドは
次の 5 種だけで、このほかのフィールドや閉じ忘れた `{` は終了符号 2 で拒否されます。

| フィールド | 置き換わるもの |
| --- | --- |
| `{seq}` | 昇順に並べたときの通し番号（1 から） |
| `{seq:幅}` | 同じ通し番号を、指定した桁数でゼロ埋めしたもの（例 `{seq:3}`） |
| `{stem}` | 拡張子を除いた名前 |
| `{ext}` | 拡張子（ドットを含む） |
| `{hash8}` | ファイルのチェックサム（SHA-256）の先頭 8 文字 |
| `{parent}` | 親フォルダの名前（直下のファイルは空） |

（`{seq}` と `{seq:幅}` は同じフィールドの 2 つの書き方なので、フィールドは
5 種です。）

## 2. 衝突

新しい名前が重なるとき、`rename` は何も作らず、衝突の一覧を出して終わります
（終了符号 1）。衝突には閉じた 3 種があります:

- 完全に同じ名前
- 大文字・小文字の違いだけの名前
- NFC／NFD の違いだけの名前

UTF-8 として読めない名前も、衝突と同じ閉じた種類で報告されます。自動的な
付け直しはありません。名前を変えて、もう 1 度計画からやり直してください。

## 3. 名前と処理記録

- `handoff/rename-receipt.json` には規則・件数・対応表のチェックサムだけが
  載り、名前は載りません。
- 旧名 → 新名の対応表は `local/rename-plan.json` に出ます。
- `--no-paths` を付けると、対応表の旧名が連番（`#1`、`#2`、…）になります。

## 4. 既知の例（他実装での検算用）

入力（3 ファイル）: `IMG_0001.jpg`・`IMG_0003.jpg`・`IMG_10.jpg`
規則: `{stem}_{seq:3}{ext}`

| 旧名 | 新名 |
| --- | --- |
| IMG_0001.jpg | IMG_0001_001.jpg |
| IMG_0003.jpg | IMG_0003_002.jpg |
| IMG_10.jpg | IMG_10_003.jpg |

実測値（2026-11-14・sandbox・Sieve Tray 2.1.1）:

- `summary.mapping_sha256` = `sha256:116da4a8e37df465c8dc5e8fd81b2d55e829ef1f41c70217f84922f72eaba57b`
- 処理記録の `digest` = `sha256:8db134edc6db0c89ce10a866507c9ea9b3bcf02109036503c39a00cebfcb588e`

（チェックサムは、同じ入力・同じ規則・同じ版でのみ再現します。）
