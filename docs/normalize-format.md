# 整理の形式（`docs/normalize-format.md`）

Sieve Tray 2.3.0（Canon）。この文書は `normalize` コマンドの観測、文字
コードの取り扱い、出力の規則、そして JSON / CSV の書き方を定める。既知の
例は「既知値」（KV-C2）で、文書から読み戻すテスト（`tests/test_canon_docs.py`）
が確かめる。

---

## 1. 観測（常に行う）

- BOM の有無と種類: UTF-8（`ef bb bf`）・UTF-32 LE / BE（`ff fe 00 00` /
  `00 00 fe ff`・**UTF-16 より先に判定する**）・UTF-16 LE / BE
  （`ff fe` / `fe ff`）。
- 改行コードの種類と件数: LF（`\n`）・CRLF（`\r\n`）・CR（`\r`）。
  2 種以上が混在するとき、兆候 `mixed_newlines` が立つ。
- NUL バイトの件数（`\x00`）。
- UTF-8 として正しいか（BOM がないか、UTF-8 の BOM のときだけ判定する。
  UTF-16 / 32 の BOM があるときは、判定の対象ではないので記録は null）。
- 文字化けの兆候（閉じた 5 種）: `replacement_char`（U+FFFD の件数）・
  `c1_controls`（U+0080〜U+009F の件数）・`nul_bytes`・`utf8_invalid`
  （BOM なしで UTF-8 として読めないとき 1）・`mixed_newlines`。

## 2. 文字コード（自動判定しない）

- BOM がある → その文字コードで厳密に読む。BOM の種類と違う並びは
  `parse_failed` で拒否する。
- BOM がなく、UTF-8 として正しい → UTF-8 で読む。
- それ以外 → `--from-encoding <名前>` が**指定されたときだけ**その文字
  コードで厳密に読む。読めない並びは置換せず `parse_failed` で拒否する。
  指定がなければ、変換せず `encoding_unknown` で拒否し、**厳密に読めた
  候補の一覧**を出す。候補の名前の順は固定で、
  `utf-8` を除いて `utf-16-le, utf-16-be, utf-32-le, utf-32-be, cp932,
  euc-jp`。すべてのバイトを読める文字コード（latin-1 など）は候補に
  入れない。

## 3. 出力の規則

- 文字コードは UTF-8（BOM なし）。
- 改行は LF（`--newline crlf` で CRLF）。CR のみの行末も LF に揃える。
- ファイルの末尾は改行 1 つ（空のファイルは空のまま）。
- `--nfc` を付けたときだけ、Unicode の NFC に正規化する（既定はしない）。
- `--check` を付けると観測だけを行い、コピーを作らない。
- `.json` は JSON の節の規則を、`.csv` は CSV の節の規則を続けて適用する
  （`--text-only` でテキストの規則だけにできる）。
- `--style jcs` の JSON は、RFC 8785 の正準形そのものが出力になる
  （正準形に末尾の改行は含まれないため、テキストの「末尾の改行 1 つ」の
  規則は `jcs` には乗らない）。

## 4. 既知の例（KV-C2）

入力 5 バイト: `41 42 43 0d 0a`（`ABC\r\n`）。
出力 4 バイト: `41 42 43 0a`（`ABC\n`）。観測は `crlf: 1`。
出力全体の SHA-256 は
**`sha256:8470d56547eea6236d7c81a644ce74670ca0bbda998e13c629ef6bb3f0d60b69`**。

## 5. JSON の書き方

- 読み込み: キーの重複は `json_duplicate_key` で拒否。`NaN` と
  `Infinity` は `json_invalid_number` で拒否。
- **pretty（既定）**: インデント 2・キーを Unicode のコードポイント順に
  並べ替え・`ensure_ascii = false`・末尾に改行 1 つ。配列の順序は変え
  ない。数値は元の表記の値を保つ（大きな整数も丸めない）。
- **jcs**: RFC 8785（JSON Canonicalization Scheme）。キーは UTF-16 の
  コード単位の順・空白なし・数値は ECMAScript の数値の文字列化の規則・
  文字列のエスケープは最小（ASCII の制御範囲だけ `\uhhhh`・小文字 16 進）。
  絶対値が 2^53 を超える整数は `json_number_unsafe` で拒否する。
  べき等で、読み直した値は等しい。
- RFC 8785 付録 B の数値の例（IEEE 754 の 16 進 → JSON 表記）で照合して
  いる（実物は rfc-editor.org から取得）。

## 6. CSV の書き方

- 区切りは `--delimiter`（既定は `,`）。区切り文字や引用符を自動判定
  しない。
- 引用符は、値が区切り文字・引用符・改行を含むとき**だけ**付く。引用符
  の中の引用符は 2 つ重ねる。
- セルの値は変えない（空白の削除・数値の書き換えをしない）。ヘッダー行
  （先頭行）はそのまま。
- 行ごとの列数が揃っていない場合は直さず、件数を `csv_ragged_rows` とし
  て観測する。
- `--sort-by <列名[,列名]>` を付けたときだけ、行を指定した列の値の
  バイト列の昇順で並べ替える（同値は元の順。安定なソート）。
- べき等で、読み直した表（セルの値）が等しい。
